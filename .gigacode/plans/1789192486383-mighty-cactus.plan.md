# План: Нормализация клиентских интерфейсов

## 1. Анализ текущего состояния

### Структура интерфейсов (иерархия):
```
HurriCacheClientInterfaceCommon (базовый)
├── HurriCacheClientRaw (скалярные: get, create, update, remove, exist, getAndDelete)
├── HurriCacheClientAtomics (атомарные: atomicCreate, atomicStore, atomicLoad, etc.)
├── HurriCacheClientMapBased (контейнерные: getContainerValue, updateContainerValue, etc.)
├── HurriCacheClientDequeBased (deque: getHead, getTail, addElementToTail, etc.)
├── HurriCacheClientRandomAccessContainers (позиционные: getElementAtPosition, removeElementAtPosition)
├── HurriCacheClientWeightBasedContainers (weight-based: getElementWithWeight)
├── HurriCacheClientHashMap (createMap, streamMap)
├── HurriCacheClientList (createList, streamList)
├── HurriCacheClientVector (createVector, streamVector)
├── HurriCacheClientSet (createSet, addElementUnordered, streamSet)
├── HurriCacheClientQueue (createQueue)
├── HurriCacheClientSortedMap (createOrderedMap, streamOrderedMap)
├── HurriCacheClientSortedSet (createOrderedSet, streamOrderedSet)
```

### Выявленные проблемы:

| Проблема | Примеры |
|----------|---------|
| **Неполные default-обёртки** | `existKey` не имеет `existKey(byte[], KeyHintData, int)` |
| **Нестандартные имена параметров** | `clientid` вместо `clientId` (remove, unlockObject, setTtl) |
| **Отсутствие джавадоков** | ~60% методов без описаний |
| **Несоответствие сигнатур** | `getAndRemoveElementAtPosition(String, KeyHintData, int)` не вызывает getDefaultTimeout() |
| **Дублирование обёрток** | `streamElementInRangeOrdered` с ContainerType вместо streamElementInRangeOrderedSet |

## 2. Целевая модель

### Скалярные/Атомарные методы (HurriCacheClientRaw, HurriCacheClientAtomics):
```java
// Основной метод (не default, byte[] key)
CompletableFuture<T> method(byte[] key, KeyHintData hint, T value, Duration ttl, int clientId, Duration timeout);

// Default обёртки — clientId по умолчанию берётся из getDefaultClientId()
default method(String key, T value) {
    return method(serializeKey(key), null, value, getDefaultTtl(), getDefaultClientId(), getDefaultTimeout());
}
default method(String key, KeyHintData hint, T value) {
    return method(serializeKey(key), hint, value, getDefaultTtl(), getDefaultClientId(), getDefaultTimeout());
}
default method(String key, T value, int clientId) {
    return method(serializeKey(key), null, value, getDefaultTtl(), clientId, getDefaultTimeout());
}
default method(byte[] key, KeyHintData hint, T value, int clientId) {
    return method(key, hint, value, getDefaultTtl(), clientId, getDefaultTimeout());
}
```

### Контейнерные методы (все контейнерные интерфейсы):
```java
// Основной метод (не default, byte[] key)
CompletableFuture<T> method(byte[] key, KeyHintData hint, ContainerValue containerValue, int clientId, Duration timeout);

// Default обёртки — clientId по умолчанию берётся из getDefaultClientId()
// Аналогично скалярным
```

### Методы без значения (getSize, existKey, lock/unlock):
```java
// Основной метод
CompletableFuture<T> method(byte[] key, KeyHintData hint, int clientId, Duration timeout);

// Default обёртки — clientId по умолчанию берётся из getDefaultClientId()
default method(String key) {
    return method(serializeKey(key), null, getDefaultClientId(), getDefaultTimeout());
}
default method(String key, KeyHintData hint) {
    return method(serializeKey(key), hint, getDefaultClientId(), getDefaultTimeout());
}
default method(String key, int clientId) {
    return method(serializeKey(key), null, clientId, getDefaultTimeout());
}
default method(byte[] key, KeyHintData hint) {
    return method(key, hint, getDefaultClientId(), getDefaultTimeout());
}
default method(byte[] key, KeyHintData hint, int clientId) {
    return method(key, hint, clientId, getDefaultTimeout());
}
```

**Правило:** Если метод в default-обёртке НЕ принимает `clientId` явно → используем `getDefaultClientId()`. Если принимает → передаём как есть.

## 5. Конвенции для джавадоков

Каждый метод должен иметь:
```java
/**
 * Краткое описание что делает метод.
 *
 * @param key      target key in byte array/string form.
 * @param hint     optional key routing hint.
 * @param value    payload/value to set (where applicable).
 * @param ttl      entry expiration duration (where applicable).
 * @param clientId identifier of the issuing client.
 * @param timeout  execution timeout duration.
 * @param pos      position/index (for positional operations).
 * @param data     list of elements to add.
 * @return a {@link CompletableFuture} describing the operation result.
 */
```

## 6. Примечания

- **Не удалять** существующие методы — только добавлять недостающие обёртки
- **Переименовывать** `clientid` → `clientId` безопасно (это параметр, не публичный API)
- **Джавадоки** писать на английском языке
- **Порядок параметров** в default-обёртках: key(String/byte[]), hint, value/data, clientId, timeout
- **TTL** по умолчанию берётся из `getDefaultTtl()`, если метод не принимает TTL явно
